## Critical findings (must fix before any accuracy claim)

### C1 — قَالَ / قُلْ normalization collision (matching false-reject)
Both the generator's `normalize()` and `matcher.js` strip dagger-alif (U+0670), so
قَٰلَ ("he said", among the most frequent Quran words) normalizes to `قل` — identical
to قُلْ ("Say!"). A correctly recited قال (ASR outputs `قال`, 3 letters) is distance 1
from expected `قل` with tolerance 0 for short words → **correct recitation rejected**.
Verified by direct computation.
**Fix (chosen):** keep `n` as-is; page data gains an optional alternate form `a`
(dagger-alif mapped to plain alif) whenever it differs from `n`; the matcher accepts a
token matching either form. Zero regression risk for all other words (e.g. الرحمٰن,
where ASR spelling matches the stripped form better).

### C2 — Kimi matcher keeps Arabic punctuation (matching false-reject)
`vendor/kimi/matcher.js:29` keeps the whole U+0600–U+06FF block, so Whisper's `،` glued
to a word survives normalization; verified: a perfect recitation of Al-Ikhlas is
**rejected outright** by one stray comma. The root `matcher.js` does NOT have this bug
(it keeps only `[ء-ي]`). **Fix:** root matcher stays canonical; port Kimi's difficulty
levels into it; retire Kimi's copy.

### C3 — Pipeline cannot run; zero-error claims unevidenced
`tools/gen_mushaf_pages.py` needs three upstream files never committed
(quran.com word-by-word DB `@kmaslesa/holy-quran-word-by-word-full-data`,
KFGQPC UthmanicHafs v22 JSON, verse-order `quran.json`). 593 of 604 page fonts missing
(source: `github.com/mustafa0x/qpc-fonts`). The "604 pages verified / 6229 of 6236 ayat"
claims have **no committed script output**; one described check (glyph-stream
char-for-char) has no implementing code at all. **Fix:** re-acquire + pin sources,
implement both checks, run for all 604 pages, commit the evidence artifacts.

### C4 — hifz-test: mic-help/typed-fallback UI is unreachable
The fixed bottom bar permanently covers the "microphone not working?" link, help box,
and typed-input fallback on most viewports (verified with Playwright: clicks land on
the progress bar). The escape hatch for exactly the users with mic trouble is dead.

### C5 — Kimi app.js: storage wipe + UTC date bug
(a) One corrupted localStorage key wipes ALL user progress via `resetState()`; no schema
validation or versioning. (b) Every "today/yesterday" comparison uses UTC — streaks and
review scheduling flip at ~3am Istanbul / ~5am Karachi / ~7am Jakarta, i.e. wrong for
essentially every target user. Duplicated at 8+ call sites.

## Major findings

- **M1** Mic stream leaks: root index.html leaks the mic on page-switch mid-recording;
  Kimi app.js leaks it on double-tap of the record button (race before `isRecording`
  is set). No `mediaRecorder.onerror` anywhere.
- **M2** Stale-transcript race (Kimi): recording can be restarted while the previous
  transcription is still running; the late result is applied to the wrong ayah.
- **M3** AudioContext leak on decode failure (Kimi) — eventually breaks all recording.
- **M4** ASR model load: not cancellable, no re-entrancy guard; retry double-click
  starts a second ~150 MB download.
- **M5** hifz-test: no `pageImage.onerror` — a failed PNG load silently produces a
  NaN-sized canvas with no message.
- **M6** deploy-test uses cloud `webkitSpeechRecognition` while the app claims
  "voice never leaves your device"; also forked the matcher inline (already diverged).
  hifz-test currently shares the cloud-ASR interim state (documented as stopgap).
- **M7** Kimi service worker: cache-first with no invalidation — deployed updates never
  reach installed users unless the cache name is hand-bumped; old caches never purged.

## Minor (recorded, fix opportunistically)

Unhandled page-JSON fetch in root index.html; no `fullscreenchange` redraw and no
keyboard nav in hifz-test; speech-recognition restart loop without backoff; unused
`ratio` field in boxes.js; orphaned `mobile-test-template.html` and loose
`apps/quran-trainer/i18n/` copy; 11 dead i18n keys in Kimi's catalogs; missing iOS
apple-touch-icon; landscape mode fills width but scrolls ~2.8 screens of height
(accepted trade-off, documented).

## Confirmed strengths (foundation to build on)

- **Single-canvas architecture** (hifz-test): image + veils in one coordinate space,
  DPR-correct; misalignment structurally impossible. Playwright-verified at mobile
  portrait/landscape and desktop: no console errors, no horizontal overflow, reveal
  flow 0→58/58 correct, and the real scanned page 604b shows word boxes landing
  exactly on the printed glyphs.
- **boxes.js data**: all 1,145 tokens across 12 pages within bounds, zero overlap
  violations, zero empty names.
- **Root matcher.js**: correct and tested; Kimi's level system is a clean addition.
- **Kimi i18n**: all 6 catalogs complete and consistent; merges cleanly into the
  existing 12-language catalog (only 6 overlapping keys, 5 identical).
- **Kimi's Quran text**: content-correct (Imlaei-vs-Uthmani spelling differences only).

## Founder decisions in force after this audit (2026-08-30 update)

- Pages 1–2 are deliberately excluded from the standard pipeline (treated separately
  at the end) — their absence from hifz-test's PAGES array is intentional, now documented.
- **Target users have weak internet and old phones. Heavy processing moves to the
  server; the client download must be minimal.** This supersedes the earlier
  on-device-ASR decision in PLAN.md.
- **ASR is server-side Whisper** (open source, best recognition quality). The
  ~150 MB model is never downloaded to the user's phone. Consequence: short audio
  clips are uploaded for recognition — privacy policy changes from "audio never
  leaves your device" to "audio is processed on our server and never stored";
  UI copy must be updated accordingly. Browser cloud SpeechRecognition remains a
  labeled stopgap only.
- **KFGQPC (King Fahd Complex) is the official open source** for Quran text, fonts,
  and page imagery.
- **The user sees the real printed mushaf page as an image** — never re-typed text.
  Pages ship as pre-rendered images (from official KFGQPC fonts/layout, print-exact)
  plus small word-box JSON; the client's per-page download is one compressed image
  (~100–200 KB) + ~5 KB of boxes. The validated single-canvas image+veil renderer
  is the display layer. The founder's tajweed-print scans stay as visual ground
  truth for QA — not as shipped assets (publisher IP).
